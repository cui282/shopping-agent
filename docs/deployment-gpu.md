# GPU inference profile

The default `docker compose --profile app up` stack is deliberately usable on CPU-only
machines. GPU inference is an opt-in deployment profile and is inference-only: this repository
does not contain SFT, Agentic RL, checkpoint updates, or fine-tuning jobs.

## Components

- `vllm` exposes an OpenAI-compatible `/v1/chat/completions` endpoint. The default model and
  served name can be replaced with `VLLM_MODEL` and `VLLM_SERVED_MODEL_NAME`.
- `embedding` is an approved Query/Item dual-tower service. It must provide `POST /query` with
  `{"query": "..."}` and `POST /item` with `{"item": {...}}`; both endpoints return
  `{"embedding": [number, ...]}` and `GET /health` must be available.
- `reranker` is an approved inference-only cross-encoder service. It must provide
  `POST /score` with the payload generated by `app/recall/reranker.py`, return
  `{"scores": [number, ...]}`, and expose `GET /health`.

The embedding and reranker image names are required explicitly so an unreviewed model image
cannot be pulled accidentally. Keep the model services on separate GPU devices where possible.

## Start

On a Linux host with Docker's NVIDIA runtime configured:

```bash
export EMBEDDING_IMAGE=registry.example.com/approved-embedding:tag
export RERANKER_IMAGE=registry.example.com/approved-reranker:tag
export VLLM_MODEL=Qwen/Qwen3-35B-A3B
export VLLM_SERVED_MODEL_NAME=shopping-agent-main
docker compose -f docker-compose.yml -f docker-compose.gpu.yml --profile gpu --profile app up --build -d
```

The backend receives `OPENAI_BASE_URL=http://vllm:8000/v1`, Query/Item endpoints on the
`embedding` service, and the Reranker endpoint on `reranker`. To use a private model gateway,
override those variables explicitly. Never commit API keys or registry credentials.

OrbStack on macOS can run the default CPU profile, but this NVIDIA profile requires a Linux host
with a compatible GPU runtime; it is not a requirement for local development or sandbox tests.
